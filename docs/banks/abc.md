# 中国农业银行（ABC）金穗信用卡电子对账单

依据：3 封真实样本，都是 2026-09 的账单，分别是 MC、VISA、银联卡（`tests/fixtures/abc/abc_{mc,visa,unionpay}_2026-09.eml`）。解析器为 `abc_html` v1。

## 1. 识别
- **发件人**：`e-statement@creditcard.abchina.com.cn`
- **主题**：`中国农业银行金穗信用卡电子对账单`
- **正文特征**：`您的信用卡账户信息`、`账务说明`、`交易明细`
- **DKIM**：有签名，`d=creditcard.abchina.com.cn`，`h=Date:From:To`，`c=relaxed/relaxed`。转发后只要正文和这三个头没变，签名仍能验证。

## 2. MIME 结构
只有一个 `text/html` 部件，`charset=utf-8`，base64 编码。没有附件，图片都是外链。

## 3. 版面：按顺序排列的叶子表格
**没有任何 id 或 class**，正文由约 37 张小 `<table>` 按顺序拼成（外面有一层容器表）。解析方法是：**按文档顺序遍历叶子表（不含子表的表），用状态机记录"当前在哪个区块、哪个分组"**。

| 顺序 | 区块开头文字 | 内容 |
|---|---|---|
| 1 | `尊敬的XXX先生:` | 问候语，含姓名，忽略 |
| 2 | `安全用卡提示` | 固定文案 |
| 3 | `您的信用卡账户信息` | 卡号、账单周期、到期还款日、本期应还款额、最低还款额（格式见 §4） |
| 4 | `额度信息` | `● 客户总授信额度`、`● 普通透支额度`（人民币，或"人民币 / 美元"） |
| 5 | `账务说明` | 汇总块：1 行表头 + 每个币种 1 行（§5） |
| 6 | `交易明细` | 表头 + 若干分组，每组是"分组行 + 交易行"（§6） |
| 7 | `分期记录` | 只有办了分期才出现，§7 |
| 8 | `积分统计`、`刷卡金统计` | 可用积分、刷卡金余额，目前不入库 |
| 9 | `温馨提示` | 固定文案 |

**账单日没有单独写出来**，取账单周期的结束日。

## 4. 账户信息区（区块 3）
| 行 | 单元格 | 示例 | 说明 |
|---|---|---|---|
| 卡号 | `卡号 Card No` \| `536113******0001` | BIN 6 位 + 掩码 + 后四位 | 后四位作为 `cards[0]`，也用来组成 `account_id = "ABC:<后四位>"` |
| 账单周期 | `账单周期 Statement Cycle` \| `2026/08/02-2026/09/01` | `YYYY/MM/DD-YYYY/MM/DD` | 对应 `period_start/end`；`statement_date = period_end` |
| 到期还款日 | `到期还款日 Payment Due Date` \| `2026/09/20` | | |
| 本期应还款额 | 表头行，之后每个币种一行 `人民币(CNY)` \| `-1,217.97` | **负数表示欠款** | 只用来交叉校验，以 §5 的汇总块为准 |
| 最低还款额 | 同上，`-781.55` | 负数表示欠款 | 取绝对值作为 `min_payment` |

## 5. 账务说明（汇总块）
- 表头有 14 格，列名之间夹着运算符。农行把整个算式直接印在账单上：
  `本期应还金额 − 本期账户溢缴款 = 上期账单应还金额 − 上期账户溢缴款 + 本期账单金额 − 本期还款、退货金额 − 本期调整金额`
- 数据行有 8 格：`[币种, 本期应还, 本期溢缴款, 上期应还, 上期溢缴款, 本期账单金额, 本期还款退货, 本期调整]`，**全部是正数，表示欠款方向**，带千分位。

| 列 | 对应 `BillBalance` 字段 |
|---|---|
| 本期应还金额 | `amount_due` |
| 本期账户溢缴款 | `deposit` |
| 上期账单应还金额 | `previous_balance` |
| 上期账户溢缴款 | `previous_deposit` |
| 本期账单金额 | `new_charges`（**已经包含**分期本金、分期利息、购汇转出） |
| 本期还款、退货金额 | `payments_credits`（**已经包含**返现、购汇转入） |
| 本期调整金额 | `adjustments = −原值`（农行的调整是减少欠款；模型里约定 `adjustments` 正数表示增加欠款） |
| — | `interest_fees = 0`（农行不单独列利息，利息作为明细行包含在"本期账单金额"里） |

## 6. 交易明细
- **表头**：`交易日期 | 入账日期 | 卡号后四位 | 交易描述 | 交易金额/币种 | 入账金额/币种(支出为-)`
- **分组行**：3 格，内容是 `['', '●', '<分组名>']`，**第一格为空**。所以不能用"以 ● 开头"来匹配，要判断第二格是不是 `●`。实测出现过的分组：`还款`、`消费`、`分期`、`其他`。
- **交易行**：6 格

| 列 | 格式 | 示例 | 说明 |
|---|---|---|---|
| 交易日期 | `YYMMDD` | `260803` | 带两位年份，不需要推断 |
| 入账日期 | `YYMMDD` | `260805` | → `post_date` |
| 卡号后四位 | 4 位数字**或空** | `0002` / `` | 购汇转账、分期本金行为空 |
| 交易描述 | 见下 | | → `description_raw` |
| 交易金额/币种 | `金额/币种`，**没有符号、没有千分位** | `39.90/AUD` | 原币金额。币种和入账币种不同时，填到 `orig_amount/orig_currency` |
| 入账金额/币种 | `±金额/币种`，**支出为负** | `-28.25/USD` | → `amount = −原值`，`currency` 取这里的币种 |

**交易描述的格式**：
- 境外消费：`境外消费  ` + **定宽**的商户名（23 个字符）+ 地点（13 个字符）+ 国家代码，例如 `境外消费  Woolworths Online      BellaVista   AU`。
  - 商户名占满 23 个字符时，后面**没有空格**，直接接地点，例如 `SQ *MISS LILLY?S - BAKENewtown`。所以要按位置切分，不能按空格切。
  - 非拉丁字符会被银行替换成 `?`，例如 `SQ *??? ...`，这是原始数据本身的问题。
  - Mastercard 的格式不同：`PlusFitness <地点>AUS`，名称、地点、国家连在一起，不是定宽。
- 网上消费：`网上消费 财付通，深圳市腾讯计算机系统有限公司`，格式是"渠道，商户"。
- 还款：`卡卡转账 <姓名>`、`银联入账 <姓名>/付款尾号:<4位>/`。
- 购汇：`自动购汇转入外币账户还款`（人民币账户，−）；`人民币账户自动购汇转入还款 汇率:6.7648500`（外币账户，+）。
- 分期：`总账分期 本期分期本金 第3/36期`、`总账分期利息 本期分期利息 第3/36期`。
- 返现：`VISA返现  Visa ABC Apple Pay 2pctCashback     SG`、`MASTER返现  ABC 1Percent rebateRebateCHN`。

**交易类型映射**（分组名 + 描述关键词）：

| 分组 | 描述特征 | `txn_type` |
|---|---|---|
| 还款 | `卡卡转账`、`银联入账`、其他还款渠道 | `REPAYMENT` |
| 还款 | `自动购汇转入外币账户还款`、`自动购汇转入还款 汇率:` | `FX_TRANSFER`，从描述里解析 `fx_rate` |
| 消费 | `境外消费`、`网上消费`、其他 | `PURCHASE` |
| 分期 | `本期分期本金` | `INSTALLMENT`，`installment="3/36"` |
| 分期 | `分期利息` | `INTEREST`，`installment="3/36"` |
| 其他 | `返现` | `REBATE` |
| 其他 | 不认识的描述 | `ADJUSTMENT`，并标 `WARN` 等待补规则 |

**自动购汇还款的完整链路**（MC 卡样本）：
1. 人民币账户：`卡卡转账 +371.53 CNY`（REPAYMENT，钱从储蓄卡进来）。
2. 人民币账户：`自动购汇转入外币账户还款 −371.53 CNY`（FX_TRANSFER，转出）。
3. 美元账户：`人民币账户自动购汇转入还款 +54.92 USD，汇率 6.76485`（FX_TRANSFER，转入）。

真实的还款只有第 1 笔，第 2、3 笔是内部换汇。统计"本月还了多少钱"时只算 REPAYMENT。

## 7. 分期记录
10 列：`分期类型 | 分期序号 | 建立日期(YYYYMMDD) | 账户状态 | 分期金额/币种 | 分期期数 | 提前还款期数 | 当期期数 | 本期应还本金/币种 | 剩余分期本金/币种`。

示例：`总账分期 | 1437 ****0000 | 20260624 | 未结清 | 23,711.33/CNY | 36 | 0 | 3 | 659.00/CNY | 21,734.33/CNY`。第一版不入库，只用来交叉校验明细里的本金行。

## 9. 已知坑
- **同一封邮件里有两套符号约定**：账户信息区"欠款为负"，账务说明"全为正"，明细"支出为负"。
- 汇总块的金额有千分位，明细金额没有。
- 正文里有 `U+FEFF`（BOM）和大量空白，统一先做空白规范化，见 [parsing.md](../parsing.md#通用工具)。
- 购汇转账行和分期本金行的卡号后四位为空。
- 每张卡单独发一封邮件，但额度是客户层面共享的。
- 只有一笔调整却没有明细时，Σ流水和净变化会差这笔调整的金额。

## 10. 样本缺口
退款、取现、年费、零消费月、每张卡再补 2 期。
