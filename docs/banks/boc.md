# 中国银行（BOC）信用卡电子合并账单

依据：2 封真实样本（`tests/fixtures/boc/`），解析器为 `boc_pdf` v1：
- `boc_visa_2026-08`：长城卓隽留学威士澳元卡，**零欠款、没有交易**，1 页，没有明细区，到期还款日为空；
- `boc_combined_2025-06`：**两张卡的合并账单**（澳元 VISA 主卡 + 长城银联卓隽卡数字版人民币卡），12 页，有欠款、有跨页明细（2026-09-19 补样本）。

下面的版面、明细区格式都已**用样本验证**；标"推断"的除外。

## 1. 识别
- **发件人**：`boczhangdan@bankofchina.com`
- **主题**：`中国银行信用卡电子账单`
- **正文特征**：HTML 里有注释 `<!--账单合并为pdf模板-->`，以及一段通知"中国银行信用卡电子合并账单，可查看和下载，请查收！"
- **附件特征**：文件名是 `中国银行信用卡电子合并账单YYYY年MM月账单.PDF`，**MIME 编码的中文**；Content-Type 是 `application/octet-stream`，不是 `application/pdf`。
- **DKIM**：✅ 有签名，`d=bankofchina.com`，`c=simple/simple`。simple 模式对任何改动都敏感，转发时只要正文被重新编码就会验证失败。

## 2. MIME 结构
`multipart/mixed` → `text/html`（1.3 KB 的通知，UTF-8）+ 附件（base64，约 350 KB）。

**识别 PDF 要看内容开头的 `%PDF-`**。按后缀或 Content-Type 判断都会漏，制作样本时就在这里踩过坑，见 [security.md](../security.md#教训2026-09-18)。

## 3. PDF 属性
- PDF 1.4，1 页 A4（595×842 pt），**未加密**，没有元数据、XMP、结构树或注释。v1 设计里写的"身份证后 6 位加密"不成立；仍然保留可选的密码解密，以防其他卡种或月份加密。
- 字体是两个子集字体 `MicrosoftYaHei` 和 `MicrosoftYaHei-Bold`（Type0、Identity-H、CIDFontType2），都带 ToUnicode，所以 **pdfplumber 能直接抽出中文**。
- 3 张图片：页眉横幅、页脚横幅、右上角"专属尊享"角标。都是通用图片，没有个人信息。
- **伪粗体**：表头的英文标签被画了两遍，抽出来会变成 `BBaallaanncc@e@#@@`、`PPaayymmeenntt dduu@e@#@@`。解决办法：
  - 用 pdfplumber 的 `page.dedupe_chars()` 去掉重叠的重复字符；
  - 定位一律用**中文标签**。

## 5. 字段映射（账户表 → `BillBalance`）
余额前面带方向标签，而不是用正负号：`存款/CRED` 表示有溢缴款，`欠款/DEBT` 表示欠款（两种都已见过）。

| 账户表的列 | 映射 |
|---|---|
| 上期存款/欠款余额 | 存款时 `previous_deposit = 值`，`previous_balance = 0`；欠款时反过来 |
| 本期支出金额（Purchase and Adjustments） | `new_charges`（**包含调整**，和农行不同） |
| 本期存入金额（Payments and Other Credits） | `payments_credits` |
| 本期存款/欠款余额 | 存款时 `deposit = 值`，`amount_due = 0`；欠款时 `amount_due = 值` |
| 账单可分期金额 | 不入库 |

- **一个账户一行**（这里是 `外币/AUD`）。**这是一张澳元单币卡**，人民币总计单独显示为 0.00。
- **汇总自洽**：(0 − 0.07) = (0 − 0.07) + 0 − 0 ✅。
- `statement_date` 取"账单日"，`due_date` 取"到期还款日"，**可以为空**。
- 合并账单可能包含多张卡：推断每张卡各有一个卡表、卡种行和账户表，要按卡种行切分。`account_id = "BOC:<后四位>"`。

## 6. 合并账单的结构（M5 实测）
- **第 1 页**：总览（到期还款日、账单日、人民币/外币欠款总计）→ 积分合计 → **卡表**（每张卡一行：`6258 9710 **** 0006`，应还和最小还款按人民币/外币分栏，空栏为 0）→ 第一张卡的**卡种行** `…(卡号：0005)` 和账户表表头。
- **每张卡一节**，依次是：卡种行 → 账户表（表头和数据行可能分在两页）→ `参考汇率` → `(AUD)外币交易明细` 或 `人民币交易明细` → 明细行。
- 两张卡之间、账单末尾夹着 **`积分奖励计划/Loyalty Plan`** 页，不属于任何一张卡。
- 页脚 `第 N 页/共 M 页`，有时数字被拆开（`共1 2 页`）。
- **每张卡生成一份 `Bill`**，`account_id = "BOC:<后四位>"`；账单日、到期还款日两张卡共用。
- **交叉校验**：卡表的应还 = 账户表的本期欠款；总览的人民币/外币欠款总计 = 各卡对应币种之和。对不上记警告。

## 7. 明细区（M5 实测）
表头：`交易日 | 银行记账日 | 卡号后四位 | 交易描述 | 存入 | 支出`（中英两行）。

- **一笔交易是一个"块"**：交易日、记账日、卡号、金额在同一行（卡号有时略高 1 点）；**描述太长会折行，折出的行在日期行的上方和下方**，最多见过三行。解析时以日期行为锚，其余行归到**纵向最近**的日期行（间距超过 25 点就报警告）。
- **描述按列宽硬折行，会从词中间切开**：`VISA BOC ZJ1PCT REBA` + `TESGP`。前一行写满到列的右边界时直接拼接，否则加空格。
- **商户后面直接粘着 3 位国家代码**：`Kelly's On KingAUS`、`Suica+ChargeJPN`、`微信-NETSTARS CO.LTDCHN`。解析器把常见国家代码切出来放进 `merchant_location`。
- **方向靠横坐标**：金额落在"存入"列是负数（还款、返现、退款），落在"支出"列是正数。金额没有正负号，也没有千分位。
- **币种**取自明细区标题（`(AUD)外币交易明细` → AUD，`人民币交易明细` → CNY）。外币卡的明细直接是卡币种金额，**没有原币金额**。
- **卡号栏**：一张卡的明细里会出现另一个尾号，那是这张卡的 **Apple Pay 设备号**（作者确认）。交易一律算在这一节的实体卡上，设备号不保存。
- **交易类型**：
  - 存入：`BOCNET`（网银还款）、含"还款""转账"是 `REPAYMENT`；含 `REBA`、"返现""返消费金""阶梯返"是 `REBATE`；其余是 `REFUND`（样本里有一笔商户退款 `ICC SYDNEYAUS`）；
  - 支出：含"年费""手续费"是 `FEE`，"利息"是 `INTEREST`，"取现"是 `CASH`，"分期"是 `INSTALLMENT`（这四种都是推断），其余是 `PURCHASE`。
- **对账实测**：澳元卡借方 883.89、贷方 1,673.54；人民币卡借方 9,097.75、贷方 12,428.56，都和账户表分毫不差。
- 解析分两层：`pdf_lines()` 把 PDF 变成"带坐标的词组成的行"，`parse_lines()` 只看这些行。测试直接构造行，不需要生成 PDF。

## 8. 已知坑
- 附件的 MIME 类型和文件名都不可靠，必须按内容识别 PDF。
- 伪粗体导致英文表头变成乱码。
- 为 0 的金额栏可能是空的，而不是 `0.00`。
- 零欠款时照样发账单，但到期还款日为空（缺账单心跳可以利用这一点：中行每月都会发）。
- DKIM 是 simple 模式，转发时比较容易被破坏。
- 付给个人的支付宝/微信收款码会带出对方的真实姓名（`支付宝-<姓名>CHN`）。加入新样本时要替换，见 [样本 README](../../tests/fixtures/README.md)。

## 9. 样本缺口
年费、利息、取现、分期；附属卡；同一张卡有人民币和外币两个账户的双币卡；再补 1 期。
