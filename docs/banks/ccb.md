# 中国建设银行（CCB）龙卡信用卡电子账单

依据：2 封真实样本，同一张 VISA 卡（`tests/fixtures/ccb/`）：
- `ccb_visa_2026-07`：账单周期 2026/06/11–07/10，**上期全额还清、本期零消费**，只有一笔还款；
- `ccb_visa_2026-06`：账单周期 2026/05/11–06/10，**69 笔**，欧洲旅行消费（欧元、瑞士法郎、美元）和返现（2026-09-19 补样本）。

消费、返现、外币的格式已经**用样本验证**；年费、利息、取现、分期、退款仍是推断。解析器为 `ccb_html` v1。

## 1. 识别
- **发件人**：`service@vip.ccb.com`，没有显示名。
- **主题**：`中国建设银行信用卡电子账单`
- **正文特征**：`龙卡信用卡对账单`、`【交易明细】`
- **DKIM**：❌ **没有签名**（`dkim=none`，只有 SPF）。转发以后就无法验证来源，只能靠发件人和正文特征判断，外加中心邮箱地址保密。见 [fetcher.md](../fetcher.md#来源校验)。

## 2. MIME 结构
`multipart/mixed` → 一个 `text/html`（`charset=utf-8`，base64）。图片是外链。

## 3. 版面：容器表嵌套子表
最外层是一张 14 行的容器表，各区块是嵌在里面的子表。解析方法是**用区块的开头文字找到对应的子表**。

**注意（M4 实测）**："应还款信息"那几行（账单周期、到期还款日、各币种的最低还款）**直接写在容器表自己的行里**，不在叶子子表里，所以不能照搬农行"只看叶子表"的做法。解析器把所有 `<tr>` 按文档顺序铺平，跳过"单元格里套着子表"的容器行，再按中文标题定位；空单元格保留，保证列的位置不变。

| 区块开头文字 | 内容 |
|---|---|
| 问候段 `尊敬的XXX 先生，您好！` | 含账单周期 `YYYY年MM月DD日 至YYYY年MM月DD日`，以及"已收到您上一账单周期（…）的还款，人民币: ￥15,450.83" |
| `龙卡信用卡对账单` | 汇总表（§4） |
| `信用信息 Credit Information` | 本期账单日、授信额度、取现额度、可用额度、积分 |
| `应还款信息 Payment Information` | 账单周期、本期到期还款日，每个币种的应还、最低还款、争议款 |
| `专项分期剩余总金额` | `CNY 0.00` |
| `【交易明细】` | 明细表（§5） |

## 4. 汇总与关键字段
**汇总表**：
- 表头 8 格：`账户币种 | 上期全部应还款额 | + | 消费/取现/其它费用 | − | 还款/退货/费用返还 | = | 本期全部应还款额`。
- 数据行 5 格：`[币种, 上期, 本期新增, 本期还款, 本期应还]`，币种写作 `人民币 （CNY）`（中间是全角括号和空格）。**美元、欧元两行即使是 0 也会列出。**

| 字段 | 位置和格式 | 示例 | 对应模型字段 |
|---|---|---|---|
| 上期全部应还款额 | 汇总表 | `15,450.83` | `previous_balance` |
| 消费/取现/其它费用 | 汇总表 | `0.00` | `new_charges` |
| 还款/退货/费用返还 | 汇总表 | `15,450.83` | `payments_credits` |
| 本期全部应还款额 | 汇总表 | `0.00` | `amount_due` |
| 本期账单日 | 信用信息，`YYYY-MM-DD` | `2026-07-10` | `statement_date` |
| 授信额度 | 信用信息 | `CNY 60,000` | 卡片元数据 |
| 积分余额 | 信用信息 | `点击查询积分` | **不提供数字**，忽略 |
| 账单周期 | 应还款信息，`YYYY/MM/DD-YYYY/MM/DD` | `2026/06/11-2026/07/10` | `period_start/end` |
| 本期到期还款日 | 应还款信息，`YYYY/MM/DD` | `2026/08/01` | `due_date` |
| 最低还款额 | 应还款信息，按币种 | `-`（不需要还款时显示 `-`） | `min_payment`，`-` 记为 0 |

- **没有溢缴款列**：`deposit = previous_deposit = 0`。如果有溢缴款，建行也许会把本期应还显示成负数，这一点**未知**。解析器（M4）的处理是**推断**：上期或本期应还为负数时，当作溢缴款（`previous_deposit` / `deposit`），对应的欠款记 0。
- **全为 0 的外币行不入库**：美元、欧元两行每期都会列出。四个数都是 0、而且这个币种没有流水时，解析器跳过这一行；**人民币行永远保留**，这样零消费的账单也能完成对账，不会变成"未对账"。
- "应还款信息"里只列有欠款的币种（样本里只有人民币），最低还款额显示 `-` 时记为 0。
- **汇总自洽**：`上期 + 本期新增 − 本期还款 = 本期应还`。实测 15,450.83 + 0 − 15,450.83 = 0 ✅。

## 5. 交易明细表
表内各行的顺序如下：

| 行 | 单元格 | 示例 |
|---|---|---|
| 标题 | 1 格 | `【交易明细】` |
| 中文表头 | 6 格 | `交易日 | 银行记账日 | 卡号后四位 | 交易描述 | 交易币/金额 | 结算币/金额` |
| 英文表头 | 6 格 | `T-Date | P-Date | Card Number | ...` |
| **账户分节** | 3 格 | `[人民币账户] RMB Account | 上期账单余额(Previous Balance) | 15,450.83` |
| **交易行** | **8 格** | `2026-06-11 | 2026-06-11 | 0004 | 手机银行 按卡转账还款  张三 | CNY | -15,450.83 | CNY | -15,450.83` |
| 结束标记 | 1 格 | `*** 结束 The End ***` |

- **交易行是 8 格**：表头只有 6 列，但"交易币/金额"和"结算币/金额"各拆成了币种和金额两格。
- **账户分节行**会给出这个币种账户的上期余额，可以和汇总表交叉校验。推断有美元消费时会出现 `[美元账户]` 分节，待样本确认。
- 日期是 `YYYY-MM-DD`，金额带千分位。
- **符号：还款为负，和我们的约定一致**，所以 `amount` 直接取结算金额，不用反转。**消费为正、返现为负已验证**（2026-06 样本）。
- **卡号栏**：用 Apple Pay 时写成 `实体卡/设备号`（如 `0004/0007`），否则只有实体卡号。设备号是 Apple Pay 的虚拟卡号，**交易算在实体卡上**，设备号不保存、不进统计。
- **外币消费**：交易币是 EUR、CHF、USD 等，结算币是人民币，汇率由银行折算，账单上不单独给出。
- **交易类型**：建行不分组，只能按符号和关键词判断。只有"还款"一种有样本支撑，其余都是**推断**：
  - 负数：描述含"还款"是 `REPAYMENT`；含"返现"、`Cashback` 或 `Rebate`（不分大小写）是 `REBATE`（已验证：`Visa 26 Apr-Sep FX RewardCashback`、`CCB CXMUSE 1pct Rebate`）；其余是 `REFUND`（推断）；
  - 正数：含"年费"或"手续费"是 `FEE`，含"利息"是 `INTEREST`，含"取现"是 `CASH`，含"分期"是 `INSTALLMENT`，其余是 `PURCHASE`（`merchant` 取整段描述）。
- 交易币和结算币不同时，交易币金额（取绝对值）记为 `orig_amount`。
- 账户分节行的"上期账单余额"和汇总表交叉校验，对不上记警告。
- 描述里用 `&nbsp;` 填充，例如 `手机银行 按卡转账还款  张三`，要先做空白规范化。

## 6. 已知坑
- ⚠️ **卡号后四位只出现在交易行里**，汇总区和账户区都没有。遇到**没有任何流水的月份**，就拿不到卡号，也就确定不了 `account_id`。对策：
  1. 优先从流水取；
  2. 取不到时，看配置里这家银行是不是只有一张卡，是就直接用；
  3. 否则标为 `WARN`，账户记为 `CCB:unknown`，等人工在 `card_aliases` 里映射。
  - **M4 实现了第 1、3 步**。第 2 步（按配置里的单卡直接指定）需要把配置传进解析器，和 `card_aliases` 一起放到 M8。
  - 一份账单里出现多个卡号（主卡加附属卡）时，账户取最小的那个，并记警告。
- 没有 DKIM，见 §1。
- 零消费月里，"本期全部应还款额"和"最低还款额"显示为 `-` 或 0，而且还款日照常给出。

## 7. 样本缺口
退款、美元账户分节（本卡外币消费都按人民币入账，可能永远不会出现）、分期、年费；再补 1 期。
