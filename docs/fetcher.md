# 邮件接入（Fetcher）

对应代码：`autobill/fetch/`，包含 `source.py`、`imap.py`、`mime.py`、`identify.py`（以后加 `dkim.py`）。第一次配置中心邮箱的步骤见 [setup.md](setup.md)。

## 邮件源抽象（MailSource）
后面的流程只认"一封原始邮件的字节"，并不关心这封邮件是从哪来的：

```python
class MailSource(Protocol):
    def iter_new(self) -> Iterator[RawMail]: ...  # RawMail = (bytes, 来源标识, 游标位置)
```

| 实现 | 用途 |
|---|---|
| `ImapSource` | 生产环境：中心邮箱，只读游标 |
| `DirectorySource` | `import-dir` 命令、离线开发和测试：读取一个目录里的 `.eml` |

测试时用 `DirectorySource` 指向 `tests/fixtures/`，不需要真实邮箱，也不需要模拟 IMAP 服务器。

### 解析器看到的邮件：`RawMessage`
`autobill/fetch/message.py`（M2）。一封邮件解码一次，交给识别和解析：

| 字段 | 内容 |
|---|---|
| `raw`、`sha256` | 原始字节和它的 sha256 |
| `message_id` | `Message-ID` 头；没有时用 `sha256:<哈希>` |
| `subject`、`from_addr` | 解码后的主题；发件人地址（小写，不含显示名） |
| `sent_at` / `email_date` | `Date` 头换算成**北京时间**；`email_date` 是那一天，决定用哪天的汇率。用固定的 +08:00（中国没有夏令时），不依赖时区数据库 |
| `html_parts`、`text_parts` | 解码后的正文，按声明的字符集解码，失败时用 GB18030 兜底 |
| `attachments` | 其余部件；`is_pdf` 按内容判断 |

转发件里的 `message/rfc822` 要在这之前拆开（M8 的 `ImapSource`），一个 `RawMessage` 永远只对应一封原始邮件。

## 邮件从哪来
**中心邮箱 = 作者自己的 iCloud 邮箱**（2026-09-19 定），这个邮箱只用于 AutoBill：
- **新账单：银行直接发到一个 iCloud 别名**（在各家银行把电子账单邮箱改成它，2026-09-19 定）；iCloud 规则把发给别名的邮件移进 `AutoBill` 文件夹。不经过任何转发，收到的就是银行原件（发件人、DKIM 签名都在），也不用维护转发规则。
- **历史账单**：作者在 QQ 网页邮箱里勾选历史账单，**分小批**"作为附件"手动转发到同一个别名。一次转发太多，QQ 会把附件变成会过期的"超大附件"链接，程序拿不到原件。
- **回填范围**：最近 12 个月（`backfill_months: 12`，以后接上）。
- 报表发回同一个 iCloud 的**主地址**，出现在收件箱；原始账单留在 `AutoBill` 文件夹，互不干扰。

**为什么是它**（比较过的方案）：

| 方案 | 结论 |
|---|---|
| 注册 QQ 小号 / 163 当中心邮箱 | 要多注册一个号；放在海外服务器上登录，容易触发风控 |
| 新注册 Gmail / 第二个 Apple ID | 稳，但作者不想再注册账号 |
| 服务器自己架邮件服务器 | 要域名、固定 IP；Oracle 封了发信的 25 端口，新 IP 发的信 iCloud 大概率拒收；维护负担大 |
| 买域名 + Cloudflare 收信 | 可行但步骤最多，还要多一套 Cloudflare 脚本；列入"以后可选" |
| 直接读 QQ 主邮箱 | 作者两次否定（授权码能看全部邮件） |
| **自己的 iCloud 邮箱 + 别名 + App 专用密码** | **采用**：不用新账号；iCloud 收发都稳；这个邮箱只用于 AutoBill，泄露面小（见 [security.md](security.md#密钥)） |

## IMAP
实现在 `autobill/fetch/imap.py`（M8a），用标准库 `imaplib`，不另装依赖。

- **iCloud**：`imap.mail.me.com`，993 端口 SSL；用户名是完整的 @icloud.com 地址；密码是 App 专用密码（环境变量 `AUTOBILL_IMAP_PASSWORD`）。
- **只读**：用 `EXAMINE` 打开文件夹，用 `BODY.PEEK[]` 抓取，不改动邮箱里的任何状态（不标已读、不移动、不删除；测试里的假服务器遇到其他命令会直接报错）。
- **不依赖"未读"标记**：每个文件夹在 `folder_cursors` 表里记 `UIDVALIDITY + last_uid`，每次只拉 UID 更大的邮件。**处理完一封才前进**：处理时出错，下次还会再读这一封。UIDVALIDITY 变了就从头再读，靠 Message-ID 去重。
- **扫描范围**：`folders`，作者是 `AutoBill` 和 `Junk`（转发来的银行邮件可能被判成垃圾邮件）。
- **只处理发给别名的邮件**（`only_to`）：垃圾邮件文件夹里的其他邮件会被跳过；AutoBill 自己的报表（带 `X-AutoBill-Report` 头）也一律跳过。
- **文件夹名不区分大小写**：配置写 `AutoBill`，邮箱里建成 `Autobill` 也能找到。配置里的文件夹邮箱里暂时没有的（比如新邮箱还没有 `Junk`），跳过并提示；一个都找不到才算出错。
- **文件夹名只能用英文**：IMAP 的非英文文件夹名要用"修改版 UTF-7"编码，程序不做这种转换，遇到中文名会直接提示改名。
- `autobill check-mailbox` 用来验证配置：登录、列出文件夹和邮件数、试登录发信邮箱，不改动也不发送任何东西。
- **各家邮箱的坑**（以后换邮箱时用）：
  - **QQ 邮箱**：要打开"允许收取自定义文件夹"；收到非标准命令时会回一个格式错误的 `* BAD`，导致客户端卡死，所以不要发非标准命令。
  - **163 / 126**：登录后、`SELECT` 之前必须发送 `ID` 命令，否则报 `Unsafe Login`（目前没有实现，换成 163 时再加）。

## MIME 处理
- **拆附件**：每个 `message/rfc822` 部件都当作一封独立的原始邮件，递归处理、各自去重。
  - **QQ 邮箱的"作为附件转发"不用 `message/rfc822`**，而是把原邮件当成普通文件附件（`application/octet-stream`），文件名是编码过的中文 `<主题>.eml`（2026-09-19 作者第一次实测发现）。所以文件名以 `.eml` 结尾、内容开头是邮件头的附件也当作原始邮件，**原样取出**，字节和银行原件完全一样。
- **解码**：按部件声明的 charset 解码，失败时用 GB18030 兜底。三家样本都是 UTF-8 + base64，其他银行可能是 GBK 并且标错字符集。
- **PDF 按内容识别**（`%PDF-` 开头），原因见 [parsing.md](parsing.md#通用工具)。
- 原始邮件以 sha256 命名落盘，见 [pipeline.md](pipeline.md)。

## 银行识别
转发之后，发件人可能变成用户自己，主题可能加上"转发："。所以识别时**三者都要看**：
1. 发件人地址或域名；
2. 主题关键词（先去掉 `转发:`、`Fwd:` 等前缀）；
3. 正文或附件特征。

具体取值见 [banks/README.md](banks/README.md) 的注册表。

- **防回环**：只处理命中注册表的邮件，AutoBill 自己发出的报表天然不会命中。`X-AutoBill-Report: true` 头只作为第二道防线。

## 来源校验
> **以后再做**。第一版只按注册表（发件人、主题、正文特征）识别银行，不校验 DKIM。

按发件人做白名单挡不住伪造：发件人可以伪造，而转发之后原始的 SPF 也已经失效。所以**按银行配置**来源校验策略：

| 银行 | 有无 DKIM | 策略 |
|---|---|---|
| 农行 | ✅ relaxed，签名覆盖 `Date:From:To` 和正文 | 用 `dkimpy` 验证。通过则"来源已验证"；失败则"来源未验证"，并在报表里标出来 |
| 中行 | ✅ simple/simple | 同上。simple 模式对改动敏感，转发时如果正文被重新编码，就会合法地验证失败。所以失败时只标记，不丢弃 |
| 建行 | ❌ 没有签名 | **不做 DKIM 校验**（否则建行永远会被标成"未验证"，提示就失去意义）。只能靠发件人、正文特征和中心邮箱地址保密防范，这是已知的残余风险 |

所有银行通用：中心邮箱地址不要公开；报表里永远不放链接。
